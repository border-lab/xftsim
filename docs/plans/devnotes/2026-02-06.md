## Completed

### Critiques #8-#10 resolved
- **#8 Multivariate DAG nodes**: Single node registers multiple outputs, fires once. Downstream depends on output names.
- **#9 Callbacks**: Simple `list[Callable]` taking Simulation object. `sim.stop = True` for early stopping.
- **#10 No backwards compat**: Clean break confirmed. No shim.

### Consistency pass — 8 specification gaps identified and resolved
1. **`||` operator removed** — Founder fallback moved to `founder=` keyword arg on `parent()`, `mother()`, `father()`. Eliminates `|` vs `||` parser precedence ambiguity.
2. **Sibling default scope** — `sibling_mean(X)` defaults to `| FID`. Explicit `|` overrides (e.g., `sibling_mean(X) | mother`).
3. **`parent(X)` = midparent** (average of mother and father) — confirmed intentional.
4. **`noise` vs `cnoise`** — `noise` = univariate, `cnoise` = multivariate (correlated across features, requires tuple LHS). `|` controls sample-level grouping orthogonally. All bare expressions implicitly `| IID`.
5. **ArchComponent registry** — DSL built-in functions organized via base class with `kind` (generative/aggregating/genetic/reference) and `accepts_grouping` metadata.
6. **Effect name resolution** — bare names in formula resolved from `effects={}` dict. Kept simple, no `meta()` wrapper.
7. **Generation 0 documented** — founders skip reproduction, `founder=` fallback kicks in. Future: optionally generate synthetic parent genotypes.
8. **Filter signature** — `filter.apply(generation, phenotype_history, pedigree_history)` accommodates cross-gen and within-gen filters.

## Testing Spec Brainstormed

10 critique points resolved for the testing plan:
1. **Parser testing** — dedicated section, categories not exhaustive lists. Parser output is `list[ArchNode]`, testable against programmatic construction.
2. **`|` grouping operator** — own test section, three resolution paths × two usage modes
3. **Multi-output nodes** — explicit tests for firing once, correct wiring
4. **Numerical tolerances** — theory-derived SE where easy, generous fixed tolerances otherwise. Never empirically tuned.
5. **Callbacks and filters** — explicit test sections, deterministic correctness tests
6. **Statistics** — `SampleStatistics` (within-sample covariance) for Phase 3. Others deferred, tested alongside implementation.
7. **I/O round-trip** — added to Phase 2 (as soon as dense format exists)
8. **"Expectation might be wrong" protocol** — agents check test code first, ask human immediately if theory unclear, never silently adjust
9. **CI strategy** — unit (<10s every commit), integration (<60s every commit), numerical (<5min PR/nightly)
10. **Performance baselines** — coarse wall-clock bounds, Phase 3+

Key design addition: **ArchNode** as internal representation. Parser is syntactic sugar over programmatic API (`arch.add(...)`). Both produce same `list[ArchNode]`.

## Post-Implementation Critique & Fixes

Self-critique identified 12 issues; 6 actionable items addressed:

### Code quality fixes
1. **Parental component duplication (#4)**: Refactored MotherComponent, FatherComponent, ParentComponent into `_ParentalComponent` base class with `_extract_values()` abstract method. ~150 lines → ~60 lines.
2. **MVGenetic duplication (#5)**: `MVGeneticComponent` now inherits from `GeneticComponent` — just overrides `name` and `__repr__`.
3. **Stat key collisions (#3)**: Fixed `_run_filters_and_stats()` in nsim.py to deduplicate stat keys (e.g., `SampleStatistics`, `SampleStatistics_1`).
4. **SibPairFilter vectorized (#6)**: Replaced O(n*k^2) Python loops with numpy-vectorized pair generation: sort-by-FID → group-by-size → `np.triu_indices` batched per family size. Also exposed `sib1_idx`/`sib2_idx` on `SibPairView` for direct index access.

### New tests added (5)
5. **Direct FID verification**: SibPairFilter test now uses exposed indices for exact FID equality check.
6. **cnoise parser tests**: Two tests for `(a, b) ~ cnoise(cov=[[...]])` and `(a, b) ~ cnoise(...) | FID`.
7. **Multiple statistics test**: Verifies deduplicated keys with two SampleStatistics instances.
8. **Custom statistic test**: Verifies custom Statistic subclass works in simulation.
9. **VT aggressive retention test**: Confirms VT works even with `retain_phenotypes=0` (retention runs after compute, so gen-1 is always available).

### Non-issues confirmed
- **_FUNC_RE regex (#2)**: Confirmed not a bug — `.*?` with `$` anchor handles nested parens correctly.
- **Retention vs VT (#1)**: The current execution order (compute → retain) means VT always has access to gen-1. Not a bug, but worth documenting.
